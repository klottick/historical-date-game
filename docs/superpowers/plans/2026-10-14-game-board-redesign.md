# Compact Card-First Game Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver readable, scroll-free 1080p play with actual-card dragging, automatic miniature-timeline navigation, honest in-place loss feedback, and on-demand sources.

**Architecture:** Keep the authoritative run/session/recovery state machine separate from a geometry-driven insertion and navigation controller. Persist attempted positions in operation feedback; use offline-built, release-bound Wikipedia link metadata only in revealed-card projection. Develop in a new worktree and switch the owned local game only after isolated integration verification.

**Tech Stack:** Existing Python 3.15/FastAPI/SQLModel/PostgreSQL, React/TanStack, generated Axios SDK, `@dnd-kit/react` and `@dnd-kit/dom` 0.5.0, Vite and Playwright. Existing httpx and Python HTML parsing suffice for article enrichment; no new dependency or library upgrade.

**Spec:** `docs/superpowers/specs/2026-10-14-game-board-redesign-design.md`

**Status:** Written spec approved on 2026-10-14; this plan awaits review and an execution-method choice. No product edits, database changes or live restarts are authorized by plan creation.

## Global Constraints

- The owner selected **A, the miniature event timeline**, over the era ribbon.
- No scoring on drag, hover, drop, navigation, or animation completion.
- Confirmed cards remain fixed.
- Verify the complete game loop at a 1920×900 CSS-pixel viewport and 100% zoom, allowing space for ordinary browser chrome. Also verify a compact 1366×768 viewport; do not require fullscreen or zoom reduction.
- Only Lock it in creates/persists the placement command and sends it.
- Once submitted, its UUID, event, revision and slot remain unchanged through transport failure or retry.
- Server replay/reload must preserve the new loss view, including after backend restart.
- Never overwrite sealed catalog/media bytes or change event IDs, dates, prompts, category assignments or selection.
- No search-result guess, invented slug, manual-review queue, or universal-coverage claim.
- Never use destructive test cleanup against the running real-game database.
- The owner waived old-data backup/preservation machinery, not these safety boundaries.
- Preserve all guest/account, Daily, scoring, attribution and BCE/CE invariants in the spec; no push, merge, deployment or invitation without a separate owner decision.
- Existing locked toolchain: Python `>=3.15,<3.16`, Node `>=26.11.1 <27`. Do not stage the privately modified tracked `.env` or private evidence.

## Review Focus

1. Preview expansion/animation moves geometry under a stationary pointer: the chosen boundary must not oscillate or change on release (Tasks 3–4).
2. Resize, device scale and browser chrome alter the visible window mid-drag: use CSS coordinates, retain a reachable target and visible controls (Tasks 3–5).
3. A tap on details or an interrupted touch drag must not score, pan the document or strand focus; reduced motion cannot strand a move (Task 4).
4. A session/owner switch or newer run revision during panning must cancel transient interaction without discarding another owner's uncertain UUID/body (Tasks 3–5).
5. Corrupt, missing or wrong-release article metadata must not expose private evidence, select the wrong article or disable gameplay (Tasks 2 and 5).
